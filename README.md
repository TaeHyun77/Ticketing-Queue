---

Docker를 활용하여 분산 환경을 구성했으며, 각 애플리케이션 인스턴스는 시작 시 Redis Pub/Sub 채널을 구독하여 이벤트를 수신할 준비를 합니다.<br><br>

**대기열 등록 과정**<br>

1. 클라이언트가 '/register'로 queueType, userId를 전송하며, 등록과 별개로 /stream에 SSE를 연결해 상태 변경을 실시간 수신합니다.

2. 등록은 단일 Lua 스크립트로 원자 처리됩니다. ZSCORE로 대기열/참가열 중복을 검사하고, 참가열에 여유가 있고 대기자가 없으면 참가열로 직행, 그렇지 않으면 INCR 카운터를 score로 대기열( Sorted Set )에 삽입합니다. 카운터의 단조 증가가 곧 선착순 정렬을 보장합니다.

3. 스케줄러가 주기적으로 대기열 선두를 참가열로 승격시키고, 승격이 발생하면 Redis Pub/Sub으로 변경 신호를 모든 서버에 전파합니다. 각 서버는 이 신호를 받아 자신에게 연결된 SSE 구독자에게 순위 재조회 또는 참가열 진입 이벤트를 전달합니다.

4. 승격된 사용자는 queueType:userId 기반 HMAC 토큰을 발급받아 쿠키에 저장하며, 타겟 페이지 진입 시 서버가 토큰을 동일 방식으로 재생성해 비교하고 참가열 TTL 만료 여부를 함께 확인하여 접근 권한을 검증합니다.<br><br>

### 주요 기능
---
1. Redis ZSet 기반 대기열 시스템을 구현하고, 대기열과 처리열을 분리하여 상태 기반 큐 구조를 설계하였습니다.

2. SSE와 Kotlin Flow를 활용하여 대기열 상태를 클라이언트에 실시간으로 전달하는 이벤트 기반 구조를 구현하였습니다.

3. Redis Sentinel 기반 Replica 구조를 구성하여 장애 발생 시에도 서비스가 지속될 수 있도록 고가용성을 확보하였습니다.

4. 우선순위 및 처리량을 고려한 하이브리드 승격 로직을 구현하여 대기열 처리 효율을 개선하였습니다.

5. k6를 활용한 부하 테스트를 통해 RPS를 단계적으로 증가시키며 시스템 처리 한계를 측정하였습니다.<br><br>

### 개선 사항
---
1. Redis Sentinel Failover 대응 설계

   Redis Sentinel failover로 인해 발생할 수 있는 데이터 유실, 락 유실, 이벤트 손실 문제를 분석하고, DB 락, 자동 재등록, 재동기화 로직 등을 통해 정합성을 유지하고 장애 상황에서도 복구가 가능하도록 설계했습니다.
   
3. SSE 이벤트 전달 구조 개선
   
   관계없는 사용자에게 전달되던 SSE 이벤트를 필터링해 불필요한 Redis 조회를 제거하고, 이벤트 종류를 명확히 분리했습니다.
   
5. 대기자보다 신규 사용자가 먼저 입장하던 선착순 역전 문제 해결
   
   참가열에 빈자리가 생겼을 때 대기자가 아닌 신규 사용자가 먼저 입장하던 문제를, 대기자 우선 승격 규칙으로 해결하여 선착순 공정성을 보장했습니다.
   
7. Redis Failover 시 데이터 유실 복구 및 재진입 보장
   
   Sentinel Failover 과정에서 발생할 수 있는 데이터 유실을 최소화하고, 통합 상태 조회 API를 통해 사용자가 자동으로 재등록하여 서비스를 계속 이용할 수 있도록 개선했습니다.
   
9. 취소와 승격 스케줄러의 Race Condition 해결
    
   사용자 취소와 승격 스케줄러가 동시에 실행되면 동일한 빈자리를 중복 계산해 중복 승격이나 참가열 불일치가 발생할 수 있었습니다. 이를 Lua 스크립트의 원자적 실행으로 해결했습니다.<br><br>

### 트러블 슈팅 💣
---
1. 다중 인스턴스 환경에서 SSE 이벤트 유실
   
   각 서버가 SSE 이벤트를 인메모리로 관리해, 특정 서버에서 발생한 이벤트가 다른 서버에 연결된 클라이언트에게 전달되지 않는 문제가 발생했습니다.
   
    → Redis Pub/Sub으로 변경 이벤트를 모든 인스턴스에 전파하고, 각 서버가 자신의 SSE 구독자에게 재전달하도록 개선했습니다.
   
2. 취소와 승격 스케줄러의 Race Condition
   
   사용자 취소와 승격이 동시에 수행되면, 조회와 삭제 사이에 사용자가 승격되어 대기열과 참가열에 동시에 존재하는 정합성 문제가 발생했습니다.
   
   → Redis Lua Script로 대기열/참가열 제거를 원자적으로 처리하여 경쟁 상태를 제거했습니다.
   
3. 다중 인스턴스 스케줄러의 중복 실행
   
   모든 인스턴스가 동일한 스케줄러를 실행하면서 승격 작업이 중복 수행되는 문제가 발생했습니다.
   
   → Redis 분산 락을 적용하여 하나의 인스턴스만 승격 작업을 수행하도록 개선했습니다.
   
4. 선착순 역전 문제
   
   참가열에 빈자리가 생기면 대기자보다 신규 요청자가 먼저 입장하는 문제가 발생했습니다.
   
   → 대기자 우선 승격 규칙을 적용하여 항상 대기열 선두 사용자가 먼저 참가열로 이동하도록 개선했습니다.
   
5. Redis Sentinel Failover 시 데이터 유실
    
   마스터 장애 시 복제가 완료되지 않은 대기열 데이터가 유실될 수 있었습니다.
   
   → AOF 영속화, min-replicas-to-write, 자동 재등록 및 통합 상태 조회 API를 적용하여 데이터 유실을 최소화하고 사용자가 자동으로 복구되도록 설계했습니다.
